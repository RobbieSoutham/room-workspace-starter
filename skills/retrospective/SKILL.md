# Retrospective

Use after substantial work that produced reusable learning. Skip routine edits with no future value.

1. Inspect the actual changes and validation evidence; do not rely on chat summaries when files or logs are available.
2. Separate what worked, what was brittle and what should change next time. Mark inference and uncertainty.
3. Check the room's `SOURCE_OF_TRUTH.md` and existing memory/changelog for the right destination and duplicates.
4. Draft a concise entry with links or paths supporting material claims. If a durable shared memory requires confirmation under local rules, show the draft first.
5. Append without overwriting prior records and use the repository's concurrency-safe procedure when one exists.

Do not promote a one-off correction into a general rule without evidence that it will recur.
