# Research task dashboard

1. Read canonical current-state records rather than inferring status from chat history.
2. Show each workstream's question, state, last verified update, next action and blocker.
3. Link to the underlying project record and evidence; keep the dashboard a view, not a second authority.
4. Mark stale or unknown fields as such and avoid exposing private details in shared views.
5. Update only after the canonical source changes.

Return a compact status view. A dashboard summary is not proof that a task, experiment or review is complete.
