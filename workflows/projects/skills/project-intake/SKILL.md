# Project intake

Use when a project is proposed or enters the shared Projects room.

1. Record the project name, accountable owner, intended users and the outcome that would count as useful.
2. Capture scope, exclusions, constraints, dependencies, stakeholders, data/privacy needs and known obligations.
3. Identify the decision owner, near-term decision, review date and evidence needed to proceed.
4. Identify the project's independent Git repository and record its submodule location under `projects/<project-name>/`; if the repository does not exist yet, make repository setup the first project prerequisite. Follow the Git submodule rules in `CLAUDE.md`.
5. Create only the minimum project record and initial milestone. Mark unanswered questions explicitly and do not treat intake as approval to spend, publish or contact others.
