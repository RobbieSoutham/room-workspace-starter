# Skill maintenance

Use when adding or changing a reusable skill.

1. Check `SKILLS.md`, the room context and nearby skills for overlap before creating a new one.
2. Give the skill a short, action-oriented name and a description that says when it applies.
3. Put only non-obvious workflow instructions in `SKILL.md`. Keep durable policy in the appropriate `knowledge/` or shared source-of-truth document and link to it.
4. Add references, scripts or assets only when the skill's real work needs them.
5. Update `SKILLS.md` and the owning room's `CONTEXT.md`; remove stale entries when retiring a skill.
6. Validate frontmatter, links, scope and any scripts. Do not add a skill solely to mirror a one-off task.
