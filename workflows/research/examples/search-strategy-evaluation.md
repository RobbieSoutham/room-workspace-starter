# Worked example: comparing two literature search strategies

> **Fictional example only.** No database search or study was conducted, and the numbers below are not results. This example shows how to plan and report a bounded evaluation.

## Starting idea

“Try a better search query for the review.”

This is an activity, not yet a research question. It does not define “better”, the comparison or the evidence needed.

## Research question

For a specified review topic and a frozen set of known eligible studies, does a revised database query retrieve a larger share of those studies than the current query, while keeping the screening workload within a pre-agreed limit?

## What would change the conclusion?

- **Support for the revision:** the revised query retrieves more of the frozen eligible set and its extra records remain within the stated screening-capacity limit.
- **Against the revision:** it retrieves no more eligible studies, or the additional screening burden exceeds the limit.
- **Inconclusive:** the eligible set is incomplete, the database interface changes, or the query cannot be run comparably.

The review team would set the actual thresholds before running the comparison. The example does not prescribe universal values.

## Design choices to record

- **Unit:** one unique record returned by a query after a declared deduplication rule.
- **Comparison:** current query versus revised query, run against the same database, fields and date range.
- **Reference set:** studies judged eligible by the review protocol before comparing queries; the process used to create this set is recorded.
- **Outcomes:** eligible reference-set records retrieved, total records returned, and screening effort required.
- **Controls:** same database platform, search date window, fields, filters and deduplication process.
- **Known limitations:** the reference set may omit eligible studies; one database may not represent all relevant sources; records can change over time.
- **Deliverable:** a table of query versions, returned records, reference-set coverage, screening burden and deviations.

## Trail to preserve

Save the protocol and query strings with dates and versions. Record the database platform, search fields, limits, export files, deduplication rule, eligibility decisions and calculation script. Keep copyrighted exports and any restricted material according to the database terms and project policy; do not put them in a public template repository.

## Interpretation boundary

If the revised query performs better on this reference set, the result supports using it for this bounded review under the recorded conditions. It does not establish that the query is best for every topic, database or review team. If the result is inconclusive, report that rather than selecting the more favourable-looking measure after the fact.
