# Research workflow design

This directory carries the reusable design and operating detail for the research workflow. It preserves the practical setup—framing, protocol, implementation, evidence traceability, verification, communication and improvement—while excluding dated local audit status, account/provider routing, named projects and personal environment paths.

Use the documents selectively. The main [research workflow](../research-workflow.md) is the short route map; these standards are deeper references for consequential or reusable work. A project should copy and adapt the relevant templates into its own repository. Do not impose every artefact on exploratory work.

| Document | Use |
|---|---|
| [Lifecycle and decision gates](lifecycle-and-gates.md) | Move work from evidence and framing through validation, communication and close-out |
| [Implementation standard](implementation-standard.md) | Make claim-bearing code traceable to sources, tests, data and results |
| [Argument and narrative standard](argument-and-narrative-standard.md) | Build literature-grounded proposals and post-result claims without hiding uncertainty |
| [Independent verification](independent-verification.md) | Set up an outcome-blind verifier and preserve its evidence and limits |
| [Workflow improvement](workflow-improvement.md) | Change reusable workflows using baselines, empirical evaluation and reversible promotion |

## Evidence and status rule

These are generic operating standards, not evidence that any implementation complies or that any workflow is superior. Keep policy, candidate designs, measured evaluations and adoption status distinct. Record version, scope, evidence, owner and effective date when adopting a local rule. If local methods or ethics requirements are stricter, follow them.
