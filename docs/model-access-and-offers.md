# Current model offers, promotions and free tiers

**Last checked: 7 November 2026.** This is the public, team-shareable offers board for the room-workspace setup. It tracks published offers, not any person's subscriptions, eligibility result, credit balance or application status. Offers and free quotas change quickly: check the linked provider terms on the day you apply or route work. The weekly review date is **14 November 2026**.

Keep account-specific state, application history, balances, verification records and keys in a private local operations record. This public register contains no account identifiers. “Open” describes a published application or claim path, not guaranteed eligibility or acceptance.

## How to read the board

- **Subscription access** is for the provider's chat or coding product; it is not API credit unless the terms explicitly say so.
- **API credit** is metered and usually expires. Check what services/models it covers, usage caps, overage and data terms.
- **Research or cloud credit** is a grant with a project scope, institution rules and a finite award. Do not value its face amount as cash.
- **Free tier** means limited provider access, not a production commitment. Check current quota in the provider console; API quotas can vary by account, model, region and date.
- Before using a free service with research material, check data retention/training terms and institutional policy. Treat a provider's input-improvement terms as unsuitable for confidential, licensed, participant, health or unpublished work unless explicitly approved.

## Review and decision record

The Ops setup runs a weekly source-diff watch over provider offer pages and free-model listings. The watch produces a change report; it does not edit or promote this board. A maintainer checks the primary source and then updates the row. Recheck this board at least weekly and immediately before applying, purchasing or changing a route. For each changed row, update its checked date, benefit, eligibility, expiry, data terms, status and official URL. Mark unverified details plainly; move expired offers to the ended section with the date. Never copy an individual's claim status, email, balance, application or verification record into this public repository.

### Keep the public starter aligned with the working setup

When the working Ops repo changes provider access, model routing, benchmarks, shared skills or workflow documentation, review the corresponding starter-repo pages in the same change. Update the public-safe mirror before closing that change and push it to the starter's own Git remote; do not assume a private-repo edit automatically reaches this public repository. Keep the setup and policy substance aligned, while removing account identities, personal directories, balances, private endpoints, secrets and other personal state. Record the review date and link to the changed source pages where useful. The checked-in source remains the live `config/ai/model_catalog.yaml`, routing policy and current benchmark board; this offers register must be updated whenever an offer/access change affects them.

Before adopting a route, compare total cost, practical availability, quotas, data terms, model/task fit, reliability, portability and exit costs. Use the [model evaluation protocol](model-evaluation-and-benchmarks.md) and [live benchmark board](model-evaluation-and-benchmarks.md#live-benchmark-board) before spending credits on substantial or claim-bearing work. No application, purchase, subscription change or billing action follows from this register alone.
